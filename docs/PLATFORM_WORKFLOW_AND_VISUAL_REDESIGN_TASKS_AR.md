# مهام تحسين ترابط المنصات وإعادة التصميم البصري

هذه القائمة تجمع جميع التوصيات الناتجة عن جولتي التدقيق الأخيرتين: تدقيق سير العمل بين الطالب والمدرب وولي الأمر والإدارة، وتدقيق الجودة البصرية مقارنة بالمنصات التعليمية العالمية. المهام مرتبة حسب الأولوية والقيمة، وكل مهمة مستقلة وقابلة للتحويل إلى Issue أو بطاقة تنفيذ.

## مبادئ ملزمة قبل التنفيذ

- [ ] عدم تنفيذ تجميل سطحي فقط؛ يعاد تنظيم التسلسل البصري وسير العمل قبل إضافة الزخارف.
- [ ] اعتماد اتجاه فني خاص ببكلمة: «أكاديمية عربية معاصرة، إنسانية، ذات لمسة مسرحية وسينمائية هادئة».
- [ ] عدم تقليد Coursera أو MasterClass حرفياً؛ الاستفادة من مبادئهما مع الحفاظ على شخصية بكلمة.
- [ ] جعل كل شاشة تجيب بسرعة: أين أنا؟ ماذا أفعل الآن؟ ماذا أنجزت؟ وما الخطوة التالية؟
- [ ] الحفاظ على وضوح القراءة والوصول الرقمي وعدم تقليل الخطوط أو أهداف اللمس لأجل الكثافة.
- [ ] عدم الإفراط في التدرجات والظلال والحركات؛ كل مؤثر بصري يجب أن يخدم المعنى أو التركيز.
- [ ] تصميم تخطيطات مخصصة للموبايل، لا مجرد تصغير تخطيط سطح المكتب.
- [ ] عدم اعتبار الحالات الفارغة دليلاً على اكتمال الميزة؛ يجب اختبار رحلة حقيقية ببيانات مترابطة.

## P0 — إصلاحات تمنع الارتباك أو المعلومات المتناقضة

### التوجيه حسب الدور

- [x] إنشاء دالة مركزية واحدة تحدد الصفحة الرئيسية لكل دور: الطالب `/dashboard`، المدرب `/trainer`، ولي الأمر `/parent`، والإدارة/الإشراف/المبيعات `/admin/overview`.
- [x] تعديل تسجيل الدخول ليحوّل المستخدم تلقائياً إلى الصفحة المناسبة لدوره عند غياب `redirect`.
- [x] التحقق من توافق `redirect` مع دور الحساب قبل استخدامه؛ لا يُحوّل المدرب إلى منصة الطالب ولا المدير إلى منصة ولي الأمر.
- [x] عند عدم توافق `redirect` مع الدور، تجاهله واستخدم الصفحة الرئيسية للدور.
- [x] إضافة اختبارات للتوجيه لكل الأدوار الأربعة، بما فيها الدخول من رابط قديم يحتوي `redirect` لدور مختلف.
- [x] توحيد سلوك «الرئيسية في المنصة» في قائمة الحساب مع دالة التوجيه المركزية نفسها.
- [x] بعد تسجيل الخروج، نقل المستخدم مباشرة إلى صفحة الدخول مع `redirect` صحيح بدلاً من تركه داخل شاشة محمية.
- [ ] تعديل رسالة تسجيل الخروج من منصة المدرب؛ لا تستخدم «هذه المنطقة مخصصة للمشرفين فقط» في مساحة المدرب.
- [x] جعل رسائل المنع وتسجيل الدخول خاصة بالدور والمنصة المطلوبة، بالعربية والإنجليزية.

### حماية حدود المنصات

- [x] جعل `/dashboard` يتطلب دور الطالب، أو يوجّه الأدوار الأخرى إلى منصاتها الصحيحة.
- [x] جعل `/parent` يتطلب دور ولي الأمر، مع استثناء إداري صريح فقط إذا وُجدت حاجة عمل موثقة.
- [x] منع المدير من رؤية واجهة ولي الأمر الفارغة لمجرد أنه مسجل الدخول.
- [x] منع المدرب وولي الأمر والمدير من رؤية منصة الطالب كأنهم طلاب بلا دورات.
- [x] توحيد Route Guards على مستوى الواجهة وعدم الاعتماد على فحوصات موزعة داخل الصفحات.
- [ ] إبقاء فحوصات الصلاحيات على الخادم مصدراً نهائياً حتى بعد تحسين حواجز الواجهة.
- [x] إضافة اختبارات وصول سلبية: كل دور يحاول فتح منصات الأدوار الأخرى ويتلقى التوجيه أو المنع الصحيح.

### توحيد الجلسات والحضور

- [x] اعتماد `live_sessions` ومواعيدها وحالتها كمصدر الحقيقة الوحيد للجلسات المباشرة لدى الطالب والمدرب وولي الأمر.
- [x] إلغاء اعتبار كل درس في دورة المدرب «حصة قادمة» تلقائياً.
- [x] إزالة الفلتر المؤقت الذي يقبل جميع الدروس ضمن `upcomingLessons`.
- [x] عدم إظهار «حصة قادمة» إلا إذا وُجد موعد فعلي قادم وحالة جلسة مناسبة.
- [x] عدم إظهار «بحاجة لتسجيل حضور» لمجرد عدم وجود سجل حضور.
- [x] إظهار مهمة تسجيل الحضور فقط لجلسة حقيقية انتهى وقتها أو بدأت وأصبحت جاهزة للرصد.
- [x] استثناء الدروس المسجلة وغير المتزامنة من مهام الحضور.
- [x] احترام حالة التسجيل النشط للطالب عند حساب الحضور والجلسات.
- [ ] توحيد المنطقة الزمنية وعرض التاريخ والوقت لدى الأدوار الثلاثة.
- [ ] إضافة حالات للجلسة: مسودة، مجدولة، مباشرة الآن، مكتملة، ملغاة، والتسجيل متاح.
- [ ] إضافة اختبار تقاطع يؤكد أن الجلسة نفسها تظهر بالمعلومات والحالة نفسيهما للمدرب والطالب وولي الأمر.
- [ ] إضافة اختبار إلغاء الجلسة وتغيير الموعد والتأكد من انعكاسه في المنصات الثلاث.

### إجراءات المدرب السياقية

- [x] جعل زر «تسجيل» يفتح شاشة حضور الدرس المحدد مباشرة، لا قائمة الدورات العامة.
- [x] جعل زر «فتح» يفتح الجلسة أو الدرس المحدد مباشرة.
- [x] جعل زر «إدارة» يفتح تفاصيل الدورة المحددة أو مساحة إدارتها الخاصة.
- [x] جعل زر «تقييم» يفتح التسليم المحدد مباشرة.
- [x] تمرير `courseId` و`lessonId` و`submissionId` في الروابط والإجراءات السياقية المناسبة.
- [x] توفير زر عودة واضح يحافظ على موضع المدرب في قائمة عمله اليومية.
- [x] بعد إتمام الحضور أو التقييم، إزالة المهمة من قائمة «ما يحتاجك الآن» دون تحديث الصفحة يدوياً.
- [x] عدم تغيير عنوان الواجهة إلى «لوحة الإدارة» عندما ينفذ المدرب مهمة ضمن صلاحياته؛ استخدم «مساحة المدرب» أو مساحة فرعية واضحة.

### حماية مشغل التعلم

- [x] مراجعة آلية اكتشاف أدوات المطور لأنها تعطي إنذارات كاذبة أثناء التصفح الطبيعي.
- [x] منع تحذير أدوات المطور من حجب الدرس عن مستخدم شرعي أو مستخدم لتقنيات الوصول.
- [x] اختبار الحماية آلياً للتأكد من عدم ظهور التحذير وعدم تعطيل تحديد النص؛ ويبقى الاختبار اليدوي لقارئات الشاشة والتكبير ضمن قبول الإصدار.
- [ ] استخدام حماية محتوى واقعية مثل الروابط الموقعة والصلاحيات والتدفق المحمي بدلاً من الاعتماد على اكتشاف DevTools.
- [ ] توفير رسالة دعم واضحة ومسار استعادة عند تعذر تشغيل المحتوى، من دون اتهام المستخدم.

## P1 — رحلة تعليمية مترابطة وواقعية

### رحلة اختبار ذهبية شاملة

- [ ] إنشاء بيانات اختبار ثابتة لدورة منشورة تضم قسماً ودروساً مسجلة ومباشرة.
- [ ] إنشاء جلسة مباشرة حقيقية بموعد قادم ورابط تجريبي وحالة واضحة.
- [ ] إنشاء جلسة مكتملة تحتاج إلى تسجيل حضور.
- [ ] تسجيل حضور وغياب وتأخر لطلاب تجريبيين مختلفين.
- [ ] إنشاء واجب فعلي بموعد تسليم وتعليمات ومعايير تقييم.
- [ ] إنشاء تسليم طالب بحالة «بانتظار التقييم».
- [ ] تقييم التسليم من المدرب مع درجة وتغذية راجعة.
- [ ] التأكد من ظهور التقييم للطالب وملخصه لولي الأمر.
- [ ] إنشاء محادثة طالب–مدرب برسالة ورد وإشعار غير مقروء.
- [ ] إنشاء محادثة ولي أمر–مدرب مرتبطة بالطالب.
- [ ] إنشاء إعلان دورة والتحقق من وصوله للطلاب المعنيين فقط.
- [ ] إنشاء طلب تسجيل ودفع تجريبي وحالة دفع ناجحة.
- [ ] إنشاء حالة دفع معلقة وحالة ملغاة وحالة استرداد.
- [ ] اختبار كود خصم صالح ومنتهي ومستنفد وغير صالح.
- [ ] إكمال الدورة وإصدار شهادة والتحقق من ظهورها في الطالب وولي الأمر والإدارة والسجل العام.
- [ ] إنشاء إشعارات لكل انتقال مهم: جلسة، واجب، تقييم، غياب، رسالة، شهادة.
- [ ] تنفيذ الرحلة كاملة كاختبار E2E متعدد الأدوار، لا كاختبارات صفحات منفصلة.
- [ ] فصل بيانات الاختبار بوضوح عن بيانات الإنتاج ومنع زرعها خارج قاعدة E2E معزولة.

### خط زمني موحد للرحلة

- [ ] تعريف حالات دورة الحياة لكل عنصر: التسجيل، الجلسة، الواجب، التسليم، التقييم، الشهادة.
- [ ] إنشاء سجل أحداث موحد يسمح بعرض «ماذا حدث ومتى ومن قام به».
- [ ] عرض الأحداث المناسبة فقط لكل دور مع احترام الخصوصية.
- [ ] جعل التغييرات التي ينفذها المدرب تنعكس فوراً لدى الطالب وولي الأمر.
- [ ] جعل إجراءات الإدارة الحساسة تنعكس بإشعار وسجل تدقيق واضحين.

## P1 — إعادة تصميم منصة الطالب

- [ ] تحويل المنصة من لوحة بيانات إلى «رحلة تطور» واضحة ومحفزة.
- [ ] تصميم بطاقة رئيسية كبيرة للخطوة التالية بدلاً من توزيع التركيز بين عدة بطاقات متساوية.
- [ ] إبقاء «تابع الآن» الإجراء البصري الأول في الشاشة.
- [ ] عرض المسار البصري للدورة: الوحدات، الدروس، المكتمل، الحالي، والقادم.
- [ ] إبراز نسبة التقدم بطريقة مرئية مع معنى، لا كرقم مجرد فقط.
- [ ] إضافة صورة المدرب أو صورة الدرس/الدورة في منطقة التعلم الأساسية.
- [ ] تصميم مراحل إنجاز واضحة تربط التقدم بالمهارات، لا بعدد الدروس فقط.
- [ ] تصميم مشغل تعلم هادئ وسينمائي يعطي الأولوية للفيديو والمحتوى.
- [ ] إضافة Dark Mode مدروس لمشغل التعلم.
- [ ] تنظيم الموارد والملاحظات والأنشطة في مساحة مساندة أو تبويبات بدلاً من تكديسها تحت الدرس.
- [ ] استخدام تخطيط Supporting Pane على الشاشات الواسعة: المحتوى الأساسي مع قائمة الدروس أو الأدوات المساندة.
- [ ] استخدام تخطيط موبايل خاص يجعل الإجراء التالي والدرس الحالي ظاهرين أولاً.
- [ ] تصميم احتفال راقٍ عند إكمال درس أو مرحلة أو دورة.
- [ ] إضافة حالات نجاح إنسانية وليست مجرد Toast أو تغيير نسبة.
- [ ] إعادة تصميم الإنجازات والشارات لتبدو جزءاً من هوية بكلمة.
- [ ] تبسيط عدد التبويبات الثانوية داخل «تعلّمي» وإظهار الأكثر استخداماً أولاً.
- [ ] جعل «تفاصيل» في بطاقة الدورة اسماً أوضح يصف ما سيفتحه.
- [x] إزالة تداخل عناصر `<main>` والحفاظ على معلم رئيسي واحد في الصفحة.
- [ ] إظهار حالة الجلسة والواجب والرسائل بلغة موجزة ومتسقة.
- [x] المحافظة على التنقل السفلي الخماسي في الموبايل مع تحسين حالة العنصر النشط.

## P1 — إعادة تصميم منصة المدرب

- [ ] جعل «ما يحتاجك الآن» البطل الرئيسي للمنصة، لا مجرد مجموعة إحصائيات.
- [ ] ترتيب قائمة اليوم: تقييمات معلقة، حضور، جلسات قادمة، رسائل عاجلة، ثم إدارة المحتوى.
- [ ] تحويل الإحصائيات إلى مؤشرات قابلة للتنفيذ وليست أرقاماً منفصلة.
- [ ] تطبيق تخطيط List–Detail على سطح المكتب: قائمة المهام أو الطلاب في جانب والتفاصيل في الجانب الآخر.
- [x] على الموبايل، تحويل تفاصيل طلاب المدرب إلى بطاقات مخصصة بدلاً من جدول مصغر.
- [ ] عرض صورة الطالب واسمه وتقدمه وآخر نشاطه وآخر تواصل معه.
- [ ] إضافة صفحة تفاصيل طالب تشمل تقدمه وحضوره وواجباته وتقييماته ورسائله.
- [ ] إبقاء ملاحظات المدرب الخاصة واضحة ومفصولة عن التغذية الراجعة التي يراها الطالب.
- [ ] استخدام ألوان دلالية محدودة وثابتة: يحتاج تدخلاً، متأخر، مكتمل، قادم.
- [ ] عدم استخدام ألوان كثيرة للتزيين أو تلوين كل بطاقة بلون مختلف.
- [ ] إضافة حالة نشطة واضحة لتبويبات «اليوم، دوراتي، طلابي، الرسائل».
- [ ] إذا كانت هذه العناصر روابط تمرير داخل الصفحة، توضيح ذلك بصرياً أو تحويلها إلى تبويبات/طرق تنقل حقيقية.
- [x] تقليل الاعتماد على جدول الطلاب على الهاتف وتحويله إلى بطاقات مختصرة.
- [ ] رفع ارتفاع حقل اختيار الدورة وحقل موضوع الإعلان إلى هدف لمس مناسب.
- [ ] عرض عدد الطلاب بصياغة عربية صحيحة بحسب العدد.
- [ ] إضافة وصول مباشر لإنشاء أو إدارة محتوى الدورة إذا كان ذلك ضمن صلاحية المدرب.
- [ ] عدم إجبار المدرب على استخدام لوحة باسم «الإدارة» لإتمام مهامه اليومية.
- [ ] إعادة تسمية أو فصل مساحة مراجعة التسليمات عن إدارة النظام العامة.
- [ ] تصميم إرسال الإعلان كعملية واضحة مع معاينة للجمهور وعدد المستلمين.
- [ ] إضافة تأكيد قبل الإرسال يذكر الدورة وعدد الطلاب دون جعل العملية مرهقة.

## P1 — إعادة تصميم منصة ولي الأمر

- [ ] تحويل المنصة إلى تقرير أسبوعي هادئ ومطمئن، لا مجموعة أرقام مجردة.
- [ ] تصميم بطاقة مميزة لكل طفل تتضمن الصورة والاسم والبرنامج والحالة العامة.
- [x] جعل بطاقة الطفل قابلة للفتح للوصول إلى تفاصيله.
- [ ] عرض تقدم كل دورة ونسبتها لكل طفل.
- [ ] عرض الدروس المكتملة والمتأخرة والقادمة.
- [ ] عرض الحضور والغياب والتأخر بطريقة بسيطة.
- [ ] عرض الواجب القادم وموعد تسليمه وحالة آخر واجب.
- [x] عرض آخر تقييم للمدرب وتغذيته الراجعة المناسبة لولي الأمر.
- [ ] عرض الجلسة القادمة والإجراء المطلوب بوضوح.
- [ ] إضافة عبارة ملخص مثل «هذا الأسبوع تحسّن في…» مبنية على بيانات فعلية.
- [ ] إضافة خط زمني مبسط لنشاط الطفل.
- [ ] عرض رسالة المدرب الأخيرة أو تنبيه التواصل المهم.
- [ ] جعل «تواصل مع المدرب» الإجراء الأساسي الوحيد عند عدم وجود إجراء أكثر أهمية.
- [ ] إضافة ملخص أسبوعي قابل للإرسال بالبريد أو الإشعار حسب تفضيلات ولي الأمر.
- [ ] إضافة إعدادات لما يصل إلى ولي الأمر: الغياب، الواجبات، التقييم، الرسائل، والشهادات.
- [x] إبقاء ربط طفل جديد واضحاً، لكن تقليل وزنه البصري بعد وجود طفل مرتبط.
- [ ] توضيح حالة رمز الدعوة: قيد الانتظار، مفعل، منتهي، أو ملغى.
- [ ] تعريب أسماء الأدوار داخل قائمة جهات الاتصال؛ عدم عرض `(student)` و`(trainer)` في واجهة عربية.
- [ ] مراجعة عبارة «منصة المتحدث الصغير» إذا كانت مساحة ولي الأمر ستخدم كل برامج بكلمة لا برنامج الأطفال فقط.
- [ ] إضافة تنقل بسيط عند توسع المنصة: نظرة عامة، أبنائي، الجلسات، الرسائل، الإعدادات.

## P1 — إعادة تنظيم لوحة الإدارة

- [ ] الحفاظ على كثافة إدارية احترافية وعدم تحويل الإدارة إلى تجربة سينمائية على حساب الكفاءة.
- [ ] إنشاء تنقل هرمي ثابت ومصنف بوضوح: نظرة عامة، CRM، LMS، التجارة، المحتوى، النظام.
- [ ] على الموبايل، عدم وضع قرابة 28 وجهة في قائمة مسطحة واحدة؛ استخدام مجموعات أو صفحة تنقل مرحلية.
